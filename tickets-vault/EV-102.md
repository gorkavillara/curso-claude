# EV-102 — Conexión SQLite sin manejo de error

**Estado:** To Do · **Prioridad:** Crítica · **Componente:** `backend/src/db/connection.ts`

## Descripción

`backend/src/db/connection.ts` abre la base de datos y ejecuta los `db.exec` de
inicialización **sin try/catch**. Si el fichero `.db` está bloqueado (otro proceso, WAL,
permisos), la excepción se propaga sin capturar y **tumba el servidor entero** en el
arranque o en la primera petición.

## Pasos para reproducir

1. Abrir el `.db` con otro proceso que mantenga un lock.
2. Arrancar el server.
3. `POST /api/tasks` → `500` y el proceso cae con `SqliteError: database is locked`.

## Log relacionado

```
2026-05-15 10:05:01 ERROR POST /api/tasks 500 SqliteError: database is locked (db/connection.ts:14)
```

## Criterio de aceptación

- Envolver la apertura/inicialización en manejo de error.
- Si la DB no está disponible → error controlado, no caída del proceso.
- No afecta al endpoint `POST /api/tasks` en sí (es capa de DB).

## Notas

No confundir con [[EV-101]] (eso es validación de entrada, otra capa).
